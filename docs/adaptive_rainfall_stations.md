# 按面积自动选择虚拟雨站

## 规则和操作

- 自动：雨量源总数 = `max(1, min(20, ceil(选区面积km² / 80)))`。
- 面积读取用户已确认的Polygon/MultiPolygon，以WGS84测地面积求和，孔洞扣除；不用矩形窗口、DEM处理范围或审核记录中的展示面积代替。
- 例如40 km²配置1个，110 km²配置2个，280 km²配置4个，398.92 km²配置5个，661 km²配置9个；超过1600 km²时自动采用20个上限，可明确指定更多。
- 手动：1～100的整数，优先于面积规则。聊天可说“设立6个虚拟雨站”“设置六个虚拟雨量站”“虚拟雨站数量改成十二个”。已经有事件时，也能结合上下文说“只修改为六个，其他沿用”。
- 恢复自动：说“恢复按面积自动布站”，或在WebUI“修改降雨”的站数输入框留空。API允许`rainfall: {station_count: null}`恢复自动，或只传站数修改并保留既有事件。
- 仅给站数而没有事件时，先保存偏好并询问日期或时段，不自行选择一场雨。给出错误数量时询问有效整数，不覆盖已有输入。

自动策略在`config/spatial.default.yaml`的`rainfall`项中配置：`automatic_station_area_km2`、`automatic_station_minimum`、`automatic_station_maximum`。配置必须有效，否则明确拒绝；无法在狭窄边界内生成足够的不同点时也拒绝，不静默减少用户要求的数量。

优先使用研究区内的现有ERA5格点。区内不足两个格点时，也可采用中心在区外、代表格网与研究区有正面积交集的现有格点；区内已有至少两个格点时，不再增加区外边缘源。真实源中心在框外或边界上时，在其格网与选区交集内部设置模型代理点，保留原始源经纬度及单源权重，不把代理点坐标冒充真实ERA5格点坐标。所有模型雨量点都严格位于研究区内部。代表格网按源表规则格点间距的半间距构建，这是明确的覆盖判定约定，不是额外获得的观测边界。目标总数不足时才补充区内虚拟站，排除孔洞及重复位置。目标总数包含现有格点与补充虚拟站，不在目标数之外额外叠加。

已有ERA5源代理点使用其对应源列（`rainfall_value_method=source_column`），非现有源的补充虚拟站使用周边ERA5插值（`rainfall_value_method=era5_interpolation`，原双线性方法；完整四格缺失时沿用原距离权重回退）；历史最大日仍按所有选中雨量源的平均日累计量筛选完整日，后续SWMM仍沿用分区IDW。降雨包携带`rainfall_source_selection.json`，记录真实源坐标、模型点坐标、覆盖范围和实际来源类型。此规则由空间MCP的通用降雨构建入口执行，适用于所有选区、显式事件和历史最大日任务，不依赖一次性案例脚本。

## 对话与版本

DeepSeek判断问答或任务，路由契约加入`station_count`与`station_count_mode`。比如“6个雨站够吗？”是知识问答，不修改站数或调用建模工具；原文实体和整数范围由程序再次校验。

修改已有降雨包的站数会保存修改前版本，撤销相关下游输入与旧运行计划，重新准备降雨和模型输入；不会自行提交新计算。指定日期或时段保持原请求，历史最大日模式则按新站点重选资料期内的最大日。运行中的任务禁止修改。旧包仍保持原站数，旧会话明确保存的4个作为手动值继续兼容，需要主动恢复自动才能更改。

降雨清单记录实际站数、自动/手动来源、计算面积、密度及上下限；交换清单保存这些依据。回答、任务背景和WebUI均可读取。当前已有模型不会因为代码升级而被改写。

## 适用边界

每80 km²的密度是本项目可配置的采样策略，不是实测雨量站设计规范。站数增加不能提高ERA5原始分辨率，也不意味着增加了独立实测信息。雨量源点和SWMM为子汇水区生成的插值雨量计是两类对象，站数目标只指雨量源点。

单站模式通过导入、降雨准备与降雨QA，明确标记`single_station_uniform`并在回答和交换清单中说明空间均一假设。自动默认至少一个；项目降雨QA最低有效站数为一个，保留自定义更严格门槛。空站包、无效时间和异常降雨仍拒绝。
