# GRASS 子汇水区划分

2026-10-09 起，新计划默认使用 `grass_watershed`。核心算法与旧永川工程一致：在局部计算 DEM 上运行 `r.watershed -s`，河网面积阈值 20 ha，按实际像元面积换算为整数像元数。`-s` 为单流向 D8；GRASS 默认的多流向模式不用于本次实现。

输入像元较粗时保留原生分辨率，不把约 12.49 m 的南川 DEM 人工插值成 5 m。分辨率、输入地形和计算范围不同，不能宣称与旧永川得到逐像元相同的分区。

## 分区与出口

- 保留 GRASS basin 栅格的原始标签，不再应用原生算法的 500 个主要分区合并目标。仍设 10,000 个分区的执行预算，超预算明确拒绝，不悄悄切换算法。
- 同一 basin 标签的多面和孔洞作为一个水文单元导出，面积从实际标签像元计数得到，避免旧版逐环导出把孔洞当分区。
- 保留用户之前要求的沿流向出流点：每个 basin 必须只有一个 GRASS drainage 跨分区/出域像元，以该像元中心为出口。结合无环检查，保证分区内像元汇向共同出口；多出口或无出口在划分阶段直接拒绝，不能用最大汇流量候选点掩盖多出口问题。没有复制旧永川 SWMM 的最低点回退策略。
- 保留可配置的独立边缘小分区筛选（默认小于 1 ha，总排除不超过已形成分区面积的 1%）。不会用它删除内部或有上下游连接的单元。
- GRASS 的边缘 NULL 区域与上述小分区筛选分别记录。NULL 未分区像元不虚构为新流域；保留和排除范围的面积之和必须等于原选区有效面积，保留范围同时用于 SWMM 和稳定性计算。

## 洼地处理与质量检查

`r.watershed` 使用 A^T 最小代价搜索处理洼地和平地，输入 DEM 不要求预先填洼，也不输出填洼高程。真实封闭洼地可通过其 `depression` 输入表示；当前与旧永川一样未设置该输入，采用贯通排水的假设。这不代表真实地表上的洼地一定不存在。

因此，原生 Priority-Flood 路径的“填洼抬高面积/最大深度”检查继续适用于原生算法；GRASS 路径不伪造这些数值。GRASS QA 直接验证原始流向、环路、域内终止点、每分区唯一出口、分区覆盖、矢量与原始标签一致、出流点、面积守恒及 SWMM 一一对应。唯一出口从原始流向重新计算；较早 schema 3 结果没有单独的唯一出口记录时也执行此检查，新结果则同时核对记录。DEM 缺值、截断边界和外部来水等局限仍需复核，使用 GRASS 不等于地形和工程模型自动正确。

官方说明：[r.watershed](https://grass.osgeo.org/grass85/manuals/r.watershed.html)。

## 运行环境和审计

启动时按 `executables.grass_cli` 或 PATH 中的 `grass`、`grass85`、`grass84`、`grass83` 查找运行器，并将解析后的绝对路径写入本次运行配置。配置了不存在的运行器时不再尝试其他路径。规划阶段就检查缺失依赖，不启动后再悄悄回退。

本机验收使用 QGIS 自带的 GRASS 8.5.0，生产代码没有写死盘符。GRASS 使用自身 Python 环境运行 worker，清除项目虚拟环境的 Python 设置，保留执行日志。

每次运行 `inputs/dem_derived/grass/` 保存计算 DEM、basin、drainage、accumulation、stream 栅格、版本和执行日志。schema 3 诊断保存参数与校验和；`calculation_mask.tif`、`excluded_boundary_mask.tif` 和 excluded 矢量清单用于面积审计。
