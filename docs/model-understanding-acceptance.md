# DeepSeek 理解能力验收

运行方式（在本机 PowerShell 中）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_model_acceptance.ps1
```

需要实际 DeepSeek 凭据和网络，会产生正常 API 调用用量。密钥通过掩码输入，仅传递给测试子进程；不写入配置、命令行或报告。无需启动 WebUI 或 MCP 服务。

验收使用生产智能体的路由、实体验证、任务上下文、状态门槛和回复代码。模型实际在线调用；空间工具只返回明确的隔离占位数据，其他操作一律拒绝。地图占位不具有科学含义，不能据此判断位置、DEM、水文计算或稳定性结果正确。

固定语料包含 8 个场景、28 轮：

- 提问和任务的语义区别，包含“帮我分析水流怎样影响边坡”和“重庆有哪些河”。
- 朝阳河的分析请求、补充所在地、引用前面河名，检查循环追问。
- 永川任务中插入知识问答和纠正，再恢复原任务。
- 永川、永定、永安区名纠正，不替用户偷偷选择无效名称。
- 经纬度定位、单个坐标纠正、更换河流不沿用旧坐标。
- 待确认边界时询问原理，不能因“对的”“取消”改变边界或启动计算。
- 位置不足先澄清，补充区县后继续，不能代替用户画边界、确认或运行。
- 尚未完成的任务经过知识问答仍能恢复。该场景与待确认边界场景使用明确标记的预置会话上下文，其他场景自然逐轮执行。

报告保存在 `runs/model_acceptance/latest/report.json` 和 `report.md`，逐轮记录用户输入、回复、预期、路由来源、模型调用成功情况、实际采用的实体、工具调用和失败原因。报告还记录影响评测的配置和生产代码指纹。

每轮自动验收要求：实际使用在线模型路由、分类符合预期、已给出的实体正确保留、问答不误触工具、知识回答不因模型失败降级、待确认边界不被知识问答改变。任何计算、自动划分或确认工具调用均为失败。服务调用失败时提前停止，标记 blocked；不能用规则降级或测试桩证明模型通过。

自动行为检查全部通过，只能标记 `behavior_passed_pending_answer_review`。仍需逐轮人工审阅回答是否切题、上下文是否理解正确、是否重复追问已有位置、是否编造完成状态。这个小样本是当前版本的功能验收，不是泛化准确率或知识正确率证明。

先保存未经修复的在线基线，再定位失败属于模型分类、实体校验、上下文、状态机还是回复层；修改后重跑同一语料比较。不要为了让单个测试通过而增加专用关键词分支。
