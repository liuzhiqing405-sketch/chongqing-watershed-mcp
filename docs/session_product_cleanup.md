# WebUI 删除会话与产物

历史列表支持“批量管理”：勾选多个对话或“全选列表”，点击“删除所选”并确认后，同时清理这些对话及其对应产物。全选仅针对当前显示的列表（最多最近 200 段），不默认选中任何对话。

批量操作逐段复用下述清理流程，接口为 `POST /api/v1/sessions/batch-delete`，请求显式提供 `session_ids`（1–200 项，先完整校验再去重）。成功与失败分别返回；运行中、文件占用或服务中断的对话保留，可在列表中重试，不影响其他所选对话的清理。若当前打开的对话删除成功，网页自动建立新会话。

单条和批量删除共用清理锁，避免同时删除时相互保留已失去引用的产物。多个所选对话共用的文件在最后一段引用它的对话成功删除后清理；未选中任务仍在使用的文件继续保留。清理跨服务仍不具备整体回滚能力，失败重试沿用 `cleanup_pending.json`。

用户在历史记录中点击删除并确认后，删除该会话的当前与历史版本产物：

- `runs/watersheds/basin-*`及对应`runs/spatial_visualizations/basin-*`。
- `runs/rainfall/rain-*`、`runs/model_inputs/package-*`。
- `exchange/exports/package-*`目录及同编号ZIP。
- `runs/hydro/inputs/hydro-input-*`、`runs/hydro/jobs/hydro-run-*`整个目录，含模型、结果、日志及派生导出件。
- `runs/hydro/visualizations/viz-*`，含属于该运行的图件。
- 会话目录、网页预览图片和下载授权。

原始DEM、水系、土地利用、ERA5、行政区边界、公共行政区地图缓存、手工上传的交换源文件保留。
其他会话（含其历史版本）仍引用的产物保留；其他服务任务/输入及跨运行比较图的依赖也保留。
浏览器另存到用户下载目录的副本不属于服务受管产物，网页无法同步删除。

由Agent协调两个独立MCP，WebUI不直接删除MCP目录。每个服务先按明确编号建立受管产物依赖图，
服务内锁保护创建/删除操作，当前和历史运行、排队计算及图件渲染都会检查；活动产物不会删除。
编号须是服务生成的12位十六进制ID，拒绝路径、链接、Windows目录联接及越界目标。
全部目标与依赖检查通过后删除，缺失目标视为已经清理，便于重试。

新创建产物立即记录到会话`products.json`，避免后续回复失败或任务修改丢失关联。
旧会话从结构化任务字段、`task_revisions.json`及完整`events.jsonl`恢复编号；不从聊天文字提取删除目标。
旧日志若已经截断且没有任何编号关联，无法安全认领对应孤立目录，不会猜测或按时间批量删除。

两个服务预检通过才开始清理。清理途中服务断开或文件被占用时，不删除会话，
`cleanup_pending.json`保存完整重试目标；该会话暂停运行/修改，继续点击删除可完成剩余清理。
这不是跨进程原子事务：已删除的部分产物不会因第二个服务失败而恢复。
